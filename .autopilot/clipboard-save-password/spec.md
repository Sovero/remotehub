# Спека: буфер обмена из сессии + сохранение пароля SSH

## §1 RDP: буфер обмена сервера → локальный

Движок по умолчанию — IronRDP (`rdpEngine: 'iron'`). `src/renderer/src/components/IronRdpView.tsx`
собирает `Backend.SessionBuilder` вручную и не регистрировал `remoteClipboardChangedCallback` —
канал cliprdr на стороне JS не обслуживался, поэтому Ctrl+C в удалённом сеансе никуда не доходил.

Решение: `sb.remoteClipboardChangedCallback(...)` отдаёт `ClipboardData` с элементами
`mimeType()/value()`; берём первый `text/*` и пишем в буфер через нативный clipboard
главного процесса. Картинки и файлы не поддерживаются.

Движок `legacy` (MsRdpClient, встроенный HWND) — буфер обмена обслуживает сам mstsc,
изменений не требует. Движок `rdpjs` (node-rdpjs) канал буфера не реализует — вне рамок.

### §1a RDP: локальный буфер → сессия (вставка внутрь удалённого стола)

1. **Отдача текста серверу**: `session.onClipboardPaste(new Backend.ClipboardData())` с
   `addText('text/plain', text)` — единый вход; хелпер `pushLocalClipboard(text, force)`.
   `force` нужен для ответа на запрос сервера: своей копии буфера WASM-сторона не держит.
2. **Ответ на запрос буфера**: `sb.forceClipboardUpdateCallback(...)` — Rust-сторона зовёт его,
   когда удалённое приложение вставляет (cliprdr FormatList/paste), и ждёт актуальный текст.
3. **Отслеживание изменений**: опрос локального буфера раз в 700 мс, только пока окно в
   фокусе (`document.hasFocus()`), через IPC-чтение из main (у `navigator.clipboard` нет
   фокуса при активной панели RDP).
4. **Ctrl+V внутри сессии**: общий путь ввода не передаёт модификаторы (они нужны хоткеям
   приложения), поэтому Ctrl+V обрабатывается отдельно: сначала текст уходит на сервер,
   затем доставляются сканкоды `Ctrl (0x1d)` + `V (0x2f)` press/release — удалённое
   приложение само запрашивает буфер и вставляет.
5. **Без эха**: текст, полученный с сервера, помечается в `clipboardReceivedRef` и обратно не
   отправляется; повторный push без `force` не выполняется. Копирование с сервера (R01)
   работает как раньше.

## §2 SSH/терминал: буфер обмена из сервера

1. **OSC 52** (`ESC ] 52 ; c ; <base64> BEL`): `term.parser.registerOscHandler(52, ...)` в
   `TerminalPane`. Так копируют tmux (`set-clipboard on`), vim/nvim с `+clipboard`, mc, screen.
   Без обработчика xterm.js последовательность молча съедает. Запрос на чтение буфера (`?`)
   игнорируется — сервер не должен читать локальный буфер.
2. **Надёжная запись в буфер**: `navigator.clipboard` требует фокуса документа и падает с
   «Document is not focused» (фокус бывает у canvas RDP или у встроенного окна legacy).
   Добавлены `clipboard:write-text` / `clipboard:read-text` (IPC, нативный `clipboard` main)
   и хелпер `src/renderer/src/lib/clipboard.ts` с откатом на браузерный API.
   Используются в Ctrl+Shift+C, Ctrl+Shift+V, ПКМ и в OSC 52.
3. **ПКМ по терминалу**: есть выделение — копируем его, нет — вставляем. Раньше клик всегда
   вставлял, и скопировать выделенный текст мышью было нельзя.
4. **Защита от многострочной вставки**: `requestPaste` пропускает в терминал сразу только
   однострочный текст; если строк больше одной — `Modal` спрашивает режим:
   «Вставить всё» (весь текст, LF→CR), «Построчно» (каждая строка уходит только по кнопке
   «Вставить строку», в диалоге видна очередная строка) или «Отменить». Тот же путь
   используют Ctrl+Shift+V, ПКМ и вставка из сниппетов/меню (`pasteToTerminal`).

## §3 SSH: сохранение пароля

1. `PasswordDialog` — чекбокс «Сохранить пароль (в следующий раз — без вопроса)», включён
   по умолчанию; значение уходит в `sessionAuth({ sessionId, password, savePassword })`.
2. `SessionManager.retryWithPassword(id, password, savePassword)` запоминает
   `pendingSavePassword` для сессии.
3. Запись в хранилище выполняется в `emit('connected')` — то есть **только после успешной
   аутентификации**; пароль от неудачной попытки не сохраняется.
4. `ipc.ts` (`setPasswordSaver`) записывает пароль в два возможных места:
   - **существующий набор** — только если он принадлежит ровно этому хосту и вход в нём
     по паролю (решение — чистая функция `reusablePasswordSet` в `credentials/dto.ts`).
     Тогда меняются только `passwordMode: 'stored'` и шифротекст (`sealSecret`);
   - **новый набор** — во всех остальных случаях: набор общий для нескольких хостов,
     в наборе ключ или SSH-агент, набора нет. Имя — имя хоста, пользователь — из прежнего
     набора; `attachCredential` привязывает новый набор к хосту.
   Так сохранение пароля не меняет способ входа у остальных профилей. Дерево рассылается
   рендереру (`profiles:changed`) — иначе привязка потерялась бы при следующей записи дерева из UI.
   Быстрое подключение без профиля: пароль не сохраняется, показывается тост.
5. Результат виден пользователю тостом: «Пароль обновлён в наборе «…»» или «Пароль сохранён
   в новом наборе «…»».

### §3a Замена пароля, который не подошёл

1. `SshSession` → `onAuthRequired` в `SessionManager` знает, был ли в этой попытке использован
   пароль из хранилища (`storedPasswordUsed`: `passwordMode === 'stored'`, есть шифротекст,
   пароля из диалога нет). В этом случае состояние `auth-required` несёт
   `savedCredential: { id, name }`.
2. Renderer (`store.applySessionState`) считает число хостов набора
   (`credentialHostIds` из `shared/tree`) и открывает диалог с `savedCredential: { name, hostCount }`.
3. `PasswordDialog` в этом режиме пишет «Сохранённый пароль набора «X» не подошёл» и даёт выбор:
   - **Все хосты набора (N)** — `scope: 'credential'`· по умолчанию;
   - **Только этот хост** — `scope: 'host'`· показывается только при `hostCount > 1`.
   Обычный запрос пароля (первое подключение) оставляет прежнюю галочку «Сохранить пароль»,
   которая соответствует `scope: 'host'`, или `'none'` без галочки.
4. Запись происходит по-прежнему только после успешного подключения (`emit('connected')`),
   теперь с scope: `retryWithPassword(id, password, scope)` → `pendingSave = { password, scope }` →
   `setPasswordSaver(host, password, scope)`.
5. `ipc.ts` решает через `replaceablePasswordSet(existing, tree, hostId, scope)`:
   `'credential'` — обновить набор (все его хосты), `'host'` — только если набор принадлежит
   ровно этому хосту; в остальных случаях создаётся новый набор и привязывается к хосту.
   Парольный набор никогда не становится единым для «своих» и «чужих» хостов без явного
   выбора «Все хосты набора» — дубли наборов больше не копятся.

## §2b VNC: буфер обмена в обе стороны

`VncViewer` не обслуживал буфер вовсе — ни копирование из VNC, ни вставка в VNC.
Сейчас используется API noVNC и тот же нативный clipboard main, что в терминале и RDP:

- **VNC → локально**: событие `clipboard` (noVNC отдаёт `detail.text`) → `copyTextToClipboard`.
- **Локально → VNC**: `rfb.clipboardPasteFrom(text)` сразу после `connect` и далее опросом
  локального буфера раз в 700 мс (только пока окно в фокусе).
- **Без эха**: текст, полученный с сервера, помечается и обратно не отправляется.
- `src/renderer/src/types/novnc.d.ts` дополнен методом `clipboardPasteFrom(text)`.

Ограничение: в легаси-протоколе (без extended clipboard) noVNC передаёт только ISO 8859-1;
серверы с extended clipboard (большинство современных) принимают и UTF-8.

Механика буфера общая с RDP: эхо-фильтр и опрос локального буфера живут в
`createClipboardSync` (`src/renderer/src/lib/clipboard.ts`), а `IronRdpView` и
`VncViewer` дают только функцию отправки текста в свою сессию и признак готовности.

## Вне рамок

| Требование | Почему не сейчас |
|---|---|
| Картинки/файлы через буфер обмена RDP | нужен file-transfer провайдер IronRDP, не заказан |
| Буфер обмена в движке rdpjs | канал cliprdr там не реализован в приложении |
| Отдельный менеджер сохранённых паролей по хостам | уже есть наборы учётных данных; дублировать не стали |
