# Спека: Remote Hub

## Задача

Пользователь держит на Windows несколько серверов: Linux-машины по SSH, Windows-машины по RDP, иногда Telnet или VNC. Сейчас для каждого протокола — отдельная программа, а адреса и логины разбросаны по блокнотам. Нужно одно окно, в котором видно всё хозяйство деревом, а подключение — в два клика, как в Termius.

## Решение

Появится настольное приложение **Remote Hub**: тёмный интерфейс в духе Termius — слева дерево профилей (группы и хосты с иконками протоколов и поиском), сверху вкладки открытых сессий, снизу статус-бар. SSH, Telnet и VNC открываются прямо в окне приложения во вкладке; RDP запускается встроенным клиентом Windows `mstsc.exe` с учётными данными из хранилища; для SSH-профилей доступен встроенный SFTP-файловый менеджер. Профили и настройки хранятся локально, пароли — в зашифрованном виде (DPAPI), без аккаунтов и облака.

## Решения по реализации

### Стек

- **Electron + React + TypeScript + Vite (electron-vite)** — на машине нет .NET SDK, Node.js есть; React — привычный слой UI; сборка и упаковка — electron-vite + electron-builder (NSIS).
- **xterm.js** + аддоны fit/search/web-links — терминал в рендерере.
- **ssh2** — SSH/SFTP/туннели в главном процессе (чистый JS, зрелый).
- **telnet-client** — Telnet в главном процессе.
- **@novnc/novnc** — VNC-просмотрщик в рендерере; транспорт — локальный мост TCP↔WebSocket в главном процессе.
- **RDP** — нативный `mstsc.exe` с `.rdp`-файлом и `cmdkey` для пароля. В выбранном стеке нет зрелого встраиваемого RDP-клиента; mstsc — эталонный клиент Windows. Это осознанное решение (см. «Вне рамок»).
- **zustand** — состояние рендерера; **nanoid** — id; **vitest** — юнит-тесты.

### Модули и границы

**Главный процесс** (`src/main`):
- `store` — профили/настройки/учётные данные: атомарная запись (tmp + rename), бэкап `.bak`, версия схемы, восстановление после повреждения.
- `crypto` — обёртка над `safeStorage` (DPAPI): шифрование строк, обратимый round-trip; в тестах подменяется фейком.
- `sessions` — фабрика сессий SSH/Telnet/VNC: единый контракт (id, open, write, resize, close, events), поток данных во вкладку через IPC.
- `rdp` — генератор `.rdp` + запуск/очистка `mstsc` и `cmdkey`.
- `vnc-bridge` — TCP-сокет до VNC-сервера + WebSocketServer на `127.0.0.1:<случайный порт>`, прозрачная пересылка байтов.
- `sftp` — операции SFTP поверх ssh2: list/stat/read/write/mkdir/rename/unlink/rmdir + прогресс.
- `tunnels` — local→remote порт-форвардинг через `ssh.forwardOut` + локальный TCP-слушатель.
- `ipc` — единый слой `ipcMain.handle` / `webContents.send`; все каналы перечислены в `ipc-contract.ts` (общие типы с рендерером).

**Preload** (`src/preload`) — `contextBridge` с типизированным `window.api`; рендерер не имеет прямого доступа к Node.

**Рендерер** (`src/renderer`): `App`, `Sidebar` (дерево, поиск, контекстные меню, drag&drop), `Tabs`, `TerminalPane` (xterm + хуки сессии), `VncViewer`, `SftpPanel`, `StatusBar`, `QuickConnect`, диалоги (хост/группа/учётные данные/туннель/новая сессия), `store` на zustand.

### Схема данных

```
TreeNode = { id, kind:'group', name, collapsed, children: TreeNode[] }
         | { id, kind:'host', name, protocol:'ssh'|'telnet'|'rdp'|'vnc',
             host, port?, username?, credentialId?, tags[], notes?,
             ssh?: { keepalive, agent, timeout }, rdp?: { domain, screenMode,
             width?, height?, multiMonitor, promptForCreds },
             vnc?: { scale, quality }, lastConnectedAt? }

CredentialSet = { id, name, username, passwordMode:'stored'|'ask',
                  passwordCipher?, keyFile?, keyPassphraseCipher?, useAgent? }

Settings = { theme:'dark'|'light', fontSize, fontFamily, accent,
             confirmOnDelete, restoreTabs, language:'ru' }
```

Файлы в userData: `profiles.json` (дерево, без секретов), `credentials.json` (только шифротексты), `settings.json`. Версия схемы — в каждом файле.

### Контракт IPC (основные каналы)

- `profiles:get/save/import/export`, `credentials:list/save/delete`
- `session:open/input/resize/close/connectState` + событие `session:data` (поток)
- `sftp:list/read/write/mkdir/rename/delete`, `tunnels:add/stop/list`
- `rdp:launch`, `check:port/ping`, `settings:get/set`, `quick:connect`
- `dialog:*` (выбор файла ключа, подтверждения)

### Поток данных терминала

Рендерер → `session:input` (id сессии, байты ввода); главный процесс пишет в поток ssh2/telnet. Главный процесс → `session:data` (id, chunk) → xterm `write`. Размер терминала после `fit` передаётся через `session:resize` (cols/rows). События состояния (`connecting/connected/error/closed`) — через `session:state`.

### RDP-поток

1. Сгенерировать `.rdp` во временной папке (адрес, порт, пользователь, домен, режим экрана, разрешение, multi-monitor, `authentication level`, `prompt for credentials` при необходимости).
2. Если пароль сохранён — `cmdkey /generic:TERMSRV/<host> /user:<user> /pass:<pass>`.
3. `spawn('mstsc.exe', [file])`, дождаться выхода, удалить `.rdp` и запись `cmdkey`.
4. Код выхода/ошибку запуска показать уведомлением во вкладке (R02.3).

### VNC-поток

Главный процесс: `net.connect(host, port)` → WebSocketServer на `127.0.0.1:0`; байты пересылаются в обе стороны. Рендерер: `RFB` из noVNC с `ws://127.0.0.1:<port>`, пароль из профиля/набора передаётся в RFB (он ведёт RFB-рукопожатие, мост протокол не знает). Ошибки аутентификации приходят как событие RFB → показываются в панели (R04.3).

## Тир

Тир **T3, 9 задач**: RDP, VNC и SFTP — независимые подсистемы с разными стеками (mstsc, noVNC-мост, ssh2-sftp), плюс отдельные волны UI. Больше 8 задач, потому что три протокольные подсистемы по-настоящему независимы.

## Швы для тестов

Поведение проверяется через публичные границы, не через внутренности:

1. **`store`** — CRUD, атомарность, восстановление из `.bak`, миграция версий (фейковая файловая система через tmpdir).
2. **`crypto`** — round-trip шифрования на фейке `safeStorage`; «шифротекст не равен открытому тексту».
3. **`rdp`-генератор** — golden-тесты содержимого `.rdp` при разных настройках профиля.
4. **`tree`-операции** — перенос узлов (сохранение целостности), поиск/фильтр, валидация, дублирование.
5. **`quick-connect`-парсер** — разбор `user@host[:port]`, ошибки ввода.
6. **конфиги сессий** — построение опций ssh2/telnet/vnc из Host+Credential (пароль подставляется из расшифрованного набора, флаги режимов попадают в опции).

Интеграционные тесты сети (реальный SSH-сервер, реальный mstsc) — вне юнит-шва; проверяются вручную при запуске приложения.

## Вне рамок

| Требование | Почему не сейчас |
|---|---|
| R04 — Serial (COM-порт) | требует нативных модулей (`node-serialport`), сборка которых в этом окружении ненадёжна; «другие протоколы» закрыты Telnet/VNC/SFTP |
| R07i — облачная синхронизация, как в Termius | требует сервер и аккаунты; в брифе их нет; хранилище локальное |
| R02 — встроенный RDP-клиент (не mstsc) | в выбранном стеке нет зрелого встраиваемого RDP; mstsc — полноценный клиент Windows; встраивание — отдельный проект |
| R08 — reverse-туннели и SOCKS | только local→remote форвардинг; остальное — следующий заход |
| R05 — команды на несколько хостов одновременно (Termius Command Palette) | крупная отдельная фича, в брифе не названа |
| R03 — запись сессии в файл | полезно, но не названо в брифе; кандидат на следующий заход |
| Мобильные клиенты, Linux/macOS | бриф: «приложение для Windows» |
