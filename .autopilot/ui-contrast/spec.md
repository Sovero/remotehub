# Спека: контраст иконок и видимость кнопок-иконок

## Проблема

Иконки рисуются `stroke = currentColor`, поэтому их контраст полностью определяется цветом текста контейнера. Найдены две группы проблем:

1. **Акцентные поверхности с белым текстом.** `.btn--primary`, `.seg-btn--active`, `.sidebar-footer .btn--active`, hover-пункты контекстного меню и сниппетов, кружки в справке использовали `color: #fff` поверх `var(--accent)`. Светлые акценты из набора (жёлтый `#d29922` 2.5:1, циан `#39c5cf` 2.1:1, фиолетовый `#c678dd` 2.9:1) — белый текст нечитаем (порог 3:1 для нетекстовых, 4.5:1 для текста).
2. **Слабые кнопки-иконки.** `--text-muted` и прозрачность (`.ctxmenu-icon { opacity: 0.75 }`) дополнительно снижают и без того тонкий штрих 1.4px у иконок 10–15px.

## Решение

### R01/R02 — контраст иконок (обе темы, все акценты)
- **`--accent-fg`** (App.tsx): цвет текста/иконок поверх акцентного фона вычисляется по относительной яркости акцента (WCAG). Белый — пока контраст ≥ 3:1 (яркость ≤ 0.30), иначе почти чёрный `#141519`.
  - По умолчанию синий `#2d95ec` — белый текст (3.17:1, как раньше).
  - Жёлтый/циан/фиолетовый — тёмный текст (7.2 / 8.7 / 6.2:1).
- Применено ко всем белым-over-акцент поверхностям: `.btn--primary`, `.seg-btn--active`, `.sidebar-footer .btn--active`, `.ctxmenu-item:hover`, `.snips-item:hover`, `.help-title-icon`, `.help-legend-n`, `.help-step-n`.
- **`.tree-tag`**: цвет `color-mix(in srgb, var(--accent) 45%, var(--text))` — акцент, смешанный с цветом текста, не «проваливается» при светлых акцентах в светлой теме (жёлтый тег ~6:1).
- Светлая тема: `--text-muted` затемнён `#67676e → #5f5f66` (мелкие иконки читаются лучше).

### R03 — видимость кнопок-иконок
- `.tabbar-new` (＋, туннели, сниппеты): idle — полный цвет текста, hover — акцентный.
- `.tab-close`, `.tab-save`: idle — цвет текста (вместо muted), hover — акцентный + фон.
- `.ctxmenu-icon`: убрана прозрачность 0.75.
- `.avail-tip__close`: полный цвет текста.
- `:focus-visible` — видимая акцентная рамка у всех кнопок-иконок (клавиатура).

### R04 — постоянная проверка (смоук `RH_SMOKE_CONTRAST`)
- Измеряет WCAG-контраст вычисленного цвета иконки/текста против эффективного фона (композиция полупрозрачных слоёв).
- Прогон: 2 темы × 6 акцентных цветов = 12 комбинаций; сканируются `.tabbar-new`, `.btn--icon`, пункты и иконки контекстного меню, `.tree-tag`, активные сегменты настроек, `.btn--primary`, плюс hover-контраст по CSS-переменным `--accent-fg`/`--accent-hover`.
- Порог 3:1 (WCAG 1.4.11); при нарушении — fail с списком комбинаций и элементов.
- Хук `window.__RH_STORE__` (main.tsx) даёт смоуку переключать тему/акцент.

### A02 — адаптивный hover
- `--accent-hover`: тёмные акценты (белый текст) **затемняются** `mixWithBlack(0.1)` — белый текст на hover ≥ 3.9:1; светлые акценты (тёмный текст) **осветляются** `mixWithWhite(0.18)`.

## Проверка
- Смоук `RH_SMOKE_CONTRAST`: 12/12 комбинаций ≥ 3.17:1, hover без нарушений — dev и packaged.
- `RH_SMOKE_ICONS` (с проверкой спиннера) — зелёный, dev и packaged.
- 107/107 тестов, typecheck обоих проектов чист.
