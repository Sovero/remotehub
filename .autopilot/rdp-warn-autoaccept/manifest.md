# Манифест требований

Источник: `brief.md`. Строку из этого списка может снять **только пользователь**.

| ID | Из брифа (дословно) | Статус | Основание | Где |
|----|---------------------|--------|-----------|-----|
| R01 | «при каждом подключении спрашивает что подключить в rdp сессию» | done | ASSUMPTION — диагностировано: это не диалог «к чему подключиться», а предупреждение безопасности mstsc о непроверенном (самоподписанном) сертификате с кнопками «Подключить»/«Отмена». mstsc в новых Windows НЕ запоминает принятый сертификат (эмпирически: CertHash в реестр не пишется даже после ручного клика «Подключить»; ни один вариант хэша сертификата не совпал) → диалог всплывает при каждом подключении | spec → T01 |
| R01.1 | «нужно сохранять настройки, а не спрашивать одно и тоже каждый раз» | done | ASSUMPTION — раз mstsc не умеет запоминать, приложение само подтверждает предупреждение: при встраивании окно диалога автоматически закрывается кликом «Подключить» (BM_CLICK по кнопке), пользователь диалог не видит; сторож повторяет подтверждение, если диалог всплыл позже | spec → T01 |
| R02i | *(подразумевается)* работа не ломается на машинах без сертификатного предупреждения (валидный сертификат) | done | ASSUMPTION — подтверждение идемпотентно: если диалога нет, клик не выполняется и ничего не меняется | spec → T01 |
| A01 | *(дополнение)* поведение совпадает с эталоном RDM (RDP внутри приложения) | done | ASSUMPTION — RDM встраивает RDP через ActiveX/IronRdp (не mstsc.exe), поэтому диалога нет вовсе; у нас — mstsc + встраивание окна + авто-подтверждение предупреждения; для пользователя результат тот же: RDP внутри, без вопросов | spec → T01 |
