# Спека: авто-подтверждение предупреждения безопасности RDP

## Задача

Пользователь запускает RDP-профиль — и при каждом подключении mstsc показывает диалог,
который выглядит как «что подключить». На деле это предупреждение системы безопасности
о непроверенном сертификате сервера («Подключить» / «Отмена»). Бриф: «нужно сохранять
настройки, а не спрашивать одно и тоже каждый раз».

## Диагностика (эмпирическая, на реальной машине)

1. `.rdp`-файл применяется: поле «Компьютер» заполняется, кодировка не виновата.
2. Всплывающий диалог — предупреждение о сертификате (класс #32770, кнопки «Подкл&ючить»/«&Отмена»).
3. **mstsc в новых Windows не запоминает принятый сертификат**: после ручного клика
   «Подключить» `CertHash` в `HKCU\...\Terminal Server Client\Servers\<host>` не появляется
   (проверено снятием реестра до/после), и при повторном запуске предупреждение появляется снова.
4. Запись `CertHash` вручную не помогает: SHA-256/SHA-1/MD5 от DER-сертификата, от публичного
   ключа и пр. не совпадают с эталоном mstsc (32 байта, но алгоритм иной — mstsc хэширует
   сертификат в своём внутреннем представлении).

**Вывод**: полагаться на «запоминание» mstsc нельзя. Приложение должно само подтверждать
предупреждение в момент его появления.

## Решение

При встраивании окна mstsc движок Win32:
- при каждом сканировании окон процесса (поиск окна для SetParent) находит диалог
  «Предупреждение системы безопасности…» (по заголовку окна, рус. и англ.),
- находит в нём кнопку «Подключить» (текст с мнемоникой `&` и без) и шлёт ей `BM_CLICK`,
- диалог закрывается мгновенно — пользователь его не видит,
- окно предупреждения исключается из кандидатов на встраивание (встраивается окно сессии, не диалог).

Сторож (тикает раз в ~2 с) повторяет подтверждение на каждый тик активной сессии — на случай,
если предупреждение всплыло уже после встраивания (mstsc показывает окно, затем диалог).
Подтверждение идемпотентно: если диалога нет, клик не выполняется.

## Пользовательские истории

| # | Метка | История | Приёмка |
|---|-------|---------|---------|
| 1 | R01 | Как пользователь, я подключаюсь по RDP и не вижу вопрос при каждом запуске | смоук против живого RDP-сервера (порт 3389): окно встроено, видимых окон «Предупреждение системы безопасности» у процессов mstsc — 0 |
| 2 | R01.1 | …и диалог не мелькает поверх встроенного рабочего стола | подтверждение срабатывает при первом же сканировании, до показа пользователю |
| 3 | R02i | …и на серверах с валидным сертификатом ничего не меняется | подтверждение без диалога — no-op; существующие смоуки и тесты не затронуты |

## Решения по реализации

1. **Подтверждение в движке** (`src/main/rdp/win32-engine.ts`): `EnumWindows` по PID →
   заголовок содержит «Предупреждение системы безопасности» / "Remote Desktop Connection" /
   /security warning/i → `EnumChildWindows` → текст кнопки без `&` содержит «Подключить»/«Connect»
   → `SendMessageW(BM_CLICK)`. Доступен как `engine.confirmSecurityWarning(pid)`.
2. **Исключение диалога из кандидатов на встраивание**: `findWindowByPid` пропускает окна,
   распознанные как предупреждение, — встраивается окно сессии, а не диалог.
3. **Сторож** (`src/main/rdp/manager.ts`): на каждом тике активной embedded-сессии вызывается
   `confirmSecurityWarning(pid)` — покрывает появление диалога после встраивания.
4. **Интерфейс** (`src/main/rdp/embed.ts`): метод `confirmSecurityWarning` добавлен в
   `RdpEmbedEngine` и noop-движок; фейк в тестах записывает вызов.
5. **Смоук** (`src/main/index.ts`, `RH_SMOKE_RDP_EMBED`): теперь против живого порта
   (`RH_RDP_PORT`, по умолчанию 3389), после встраивания ждёт (до 8 с), пока у живых
   mstsc-процессов не останется видимых окон «Предупреждение системы безопасности».

## Вне рамок

| Требование | Почему не сейчас |
|---|---|
| Полный отказ от mstsc в пользу собственного RDP-клиента (как IronRdp у RDM) | отдельная крупная работа: нужен нативный RDP-протокол; текущий путь (mstsc + встраивание + авто-подтверждение) даёт тот же пользовательский результат |
| Настройка «предупреждать о недоверенном сертификате» (вкл/выкл) | бриф говорит «не спрашивать одно и то же каждый раз»; авто-подтверждение — прямое исполнение; переключатель — не заказан |
