# 01 — Ядро IronRDP: TCP-прокси и жизненный цикл сессии

**Требования:** R08, R08.1, R08.2, R05.1, R04.1
**Blocked by:** —
**Status:** ready

## Что должно заработать

Пользователь дважды кликает по RDP-хосту. Main-процесс открывает TCP-соединение
с Windows-сервером, проксирует байты в renderer, IronRDP WASM устанавливает
сессию через CredSSP (NLA) или стандартный RDP Security Layer — и присылает
первый битмап. Вкладка показывает спиннер «Подключение к 10.10.51.2…» до
первого кадра.

## Из брифа, дословно

> «RDP-подключение должно открываться внутри вкладки приложения»
> «Подключение работает с серверами Windows, требующими NLA»

## Разделы спеки

Истории 1, 2, 5, 6. Решения: Архитектура, Модули (RdpIronManager, RdpIronProxy), Жизненный цикл.

## Критерии приёмки

- [ ] `RdpIronManager.connect()` открывает TCP :3389, согласует TLS, проходит CredSSP/NLA
- [ ] `RdpIronProxy` прозрачно гонит байты TCP ↔ IPC binary channel
- [ ] Сервер без NLA тоже работает (стандартный RDP Security Layer)
- [ ] При обрыве TCP рендерер получает `ironrdp:state { disconnected, error }`
- [ ] При неверном пароле — `ironrdp:state { disconnected, error: 'Неверное имя пользователя или пароль' }`
- [ ] Старый `RdpManager` (mstsc) не вызывается при запуске RDP-сессии
- [ ] Типы и IPC-контракты в `ipc-contract.ts` расширены, `preload/index.ts` обновлён
- [ ] Тест: `RH_FAKE_RDP=1` smoke-режим эмулирует успешное подключение без TCP
