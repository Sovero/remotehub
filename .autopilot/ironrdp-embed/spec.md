# Спека: Встраивание RDP через IronRDP

## Задача

Пользователь хочет подключаться к удалённым Windows-рабочим столам. Сегодня
подключение идёт через `mstsc.exe`: создаётся внешнее окно, всплывает чёрная
панель BBAR, SetParent борется с Z-порядком Chromium, верификация встраивания
ломается на стилях окна. В результате рабочий стол не виден внутри вкладки —
вместо него заглушка «Remote Desktop подключён», а mstsc висит отдельным окном.
Сервер 10.10.51.2 требует NLA — это делает невозможным использование старых
JS-библиотек вроде node-rdpjs (2015).

## Решение

RDP-протокол реализуется библиотекой IronRDP, скомпилированной в WebAssembly.
Рендеринг — в `<canvas>` внутри React-компонента `RdpCanvas`. Никаких внешних
процессов, никаких HWND, никакого SetParent. Подключение — чистый TCP :3389,
проксированный через main-процесс Electron в renderer.

При первом подключении пользователь дважды кликает по хосту в дереве профилей —
открывается вкладка, через 2–5 секунд появляется рабочий стол. При повторном —
то же самое. Если соединение рвётся, вкладка показывает ошибку с кнопкой
«Переподключиться».

## Решения по реализации

### Стек

- **IronRDP** (`@devolutions/iron-remote-desktop` + `@devolutions/iron-remote-desktop-rdp`) — веб-компонент, WASM-модуль. *Почему*: npm-пакет, NLA из коробки, production-grade (Cloudflare, Devolutions Gateway), не требует Rust-тулчейна для сборки.
- **TCP-прокси** в main-процессе — net.Socket. *Почему*: WASM в renderer не может открывать TCP-сокеты (браузерный песочница). Main открывает соединение, проксирует байты туда-обратно через IPC.
- **Canvas-рендеринг** — HTML5 Canvas 2D внутри React-компонента. *Почему*: `<iron-remote-desktop>` — это веб-компонент, он сам управляет canvas.

### Архитектура

```
Renderer                          Main Process                    Network
┌──────────────────────┐          ┌──────────────────┐          ┌────────┐
│ <iron-remote-        │  IPC     │ RdpIronManager   │   TCP    │ Windows│
│   desktop>           │◄────────►│                  │◄────────►│ Server │
│                      │  binary  │ net.Socket proxy │  :3389   │ :3389  │
│ Canvas WASM          │  channel │                  │          │        │
└──────────────────────┘          └──────────────────┘          └────────┘
```

### Модули

- **RdpIronManager** (`src/main/rdp/iron-manager.ts`) — управление сессиями: connect/disconnect, TCP-прокси, IPC-мосты.
- **RdpIronProxy** (`src/main/rdp/iron-proxy.ts`) — net.Socket ↔ IPC binary channel.
- **RdpCanvas** (`src/renderer/src/components/RdpCanvas.tsx`) — обёртка над `<iron-remote-desktop>`, захват мыши/клавиатуры.
- **IPC-контракты** — расширить существующие rdpjs-каналы либо добавить новые `ironrdp:*`.
- **Старый код** — `rdp/manager.ts`, `rdp/win32-engine.ts`, `rdp/launcher.ts`, `rdp/generator.ts` остаются на диске, но не вызываются: `launch()` всегда идёт через RdpIronManager.

### Жизненный цикл сессии

```
launch → connect TCP → TLS handshake → CredSSP (NLA) → MCS Connect
→ Capabilities → Licensing → Session Ready → bitmap stream → Canvas render
```

### Разрешение

- Размер canvas = `getBoundingClientRect()` rdp-pane.
- ResizeObserver → Display Control PDU → сервер меняет разрешение.
- Дропдаун разрешения в тулбаре сохраняет значение в профиль (host.rdp.width/height) — применяется при следующем подключении.

### Сертификат

- IronRDP выбрасывает событие при недоверенном сертификате.
- `rdpAutoAcceptCert=true` → авто-принятие.
- `rdpAutoAcceptCert=false` → отправка `rdp:certificate { pending: true }` в renderer → баннер во вкладке.

### Существующие фичи

- **История**: `RdpjsClientManager` (переименовать в `RdpProtocolManager`) записывает HistoryEntry.
- **Статусбар**: адрес сервера из `sessionId` → `activeSessions`.
- **Immersive**: CSS-класс `rdp-pane--immersive` скрывает тулбар, canvas на весь viewport.
- **Хоткеи**: Ctrl+Shift+F = immersive, Escape = выход из immersive.

## Швы для тестов

1. **RdpIronManager** — публичный интерфейс: `connect(opts) → Promise<RdpLaunchResult>`, `disconnect(sessionId)`, `sendMouse/sendKey`. Тесты подменяют net.Socket.
2. **RdpCanvas** — React-компонент с пропсами `sessionId, width, height, connected`. Тесты проверяют рендер canvas и обработчики событий.
3. **IPC** — контракты в `ipc-contract.ts`. Тесты вызывают invoke/handle и проверяют типы.
4. **Интеграционный тест** — `RH_FAKE_RDP=1` smoke-режим: не открывает TCP, эмулирует bitmap stream.

## Вне рамок

| Требование | Почему не сейчас |
|---|---|
| VNC через IronVNC | В брифе только RDP; VNC остаётся на текущем noVNC-мосте |
| SFTP/SSH/Telnet | Не затрагиваются — остаются на ssh2 |
| Аудио-проброс (RDPSND) | IronRDP поддерживает, но требует отдельной интеграции — следующий заход |
| Буфер обмена (CLIPRDR) | IronRDP поддерживает, отложено до аудио |
| Проброс дисков (RDPDR) | Требует virtual channel driver — выходит за рамки «рабочий стол внутри вкладки» |
