Требование снимается только пользователем.

| ID | Требование (из запроса) | Статус | Реализация | Ссылки |
|---|---|---|---|---|
| R01 | «Распространи ту же политику на буфер обмена из RDP и VNC: сейчас текст с удалённого стола и VNC-сервера попадает в буфер Windows молча» | done | `offerRemoteClipboard` из `remoteClipboardChangedCallback` (RDP) и события `clipboard` (VNC); `createClipboardSync.applyRemote` → `markRemote`, запись в буфер больше не происходит без политики | spec §2, §4 → T01 |
| R02 | «Предложи и сделай общую настройку «разрешить / спрашивать / запретить» с тем же пределом размера» | done | `Settings.clipboardPolicy` / `clipboardMaxBytes` (общие для SSH, RDP, VNC), миграция старых ключей `osc52*`, общий диалог `ClipboardAskDialog` | spec §1, §3 → T01 |

## Проверка

- Автотесты: `tests/clipboard-policy.test.ts` (решения политик, предел в байтах
  UTF-8, предпросмотр, `dispatchRemoteCopy` с источником), `tests/osc52.test.ts`
  (разбор OSC 52). Полный прогон: 257 passed / 2 skipped; `tsc` по обеим
  конфигурациям — 0.
- Вживую не проверялось: RDP и VNC требуют живого сервера и окна приложения.
  Проверить: при `ask` диалог показывает «RDP · хост» / «VNC · вкладка» и «Не
  копировать» не меняет буфер; при `deny` буфер не меняется молча; при `allow`
  текст попадает сразу; текст больше предела не копируется и даёт тост.
