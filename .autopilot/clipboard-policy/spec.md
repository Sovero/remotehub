# Спека: общая политика буфера обмена

## §1 Настройки

Поля `Settings` переименованы из `osc52*` в общие — политика больше не про один
протокол:

| Поле | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `clipboardPolicy` | `'allow' \| 'ask' \| 'deny'` | `'ask'` | писать ли текст из удалённой сессии в буфер |
| `clipboardMaxBytes` | `number` | `100000` | предел размера в байтах, `0` — без предела |

**Миграция.** `main/store` при загрузке переносит старые ключи `osc52Policy` и
`osc52MaxBytes` в новые, если новых в файле ещё нет: у тех, кто успел выставить
запрет, он не должен тихо вернуться к «спрашивать».

Форма настроек: селект политики и числовое поле предела с подписью «Буфер обмена
из удалённых сессий (SSH, RDP, VNC)».

## §2 Одна дорога для всех протоколов

`src/shared/clipboard-policy.ts` — чистая логика:

- `clipboardDecision(policy, maxBytes, text)` → `'copy' | 'ask' | 'ignore' | 'too-large'`;
- `clipboardPreview(text)` — первые 4 строки по 120 символов (одна длинная строка
  не раздувает диалог);
- `dispatchRemoteCopy(policy, maxBytes, text, source, effects)` — единственное место,
  где решение превращается в действие (`copy` / `ask` / `tooLarge`);
- `utf8Length`, `formatBytes`.

`src/renderer/src/lib/remote-clipboard.ts` — `offerRemoteClipboard(text, source)`:
читает настройки в момент события, пишет через нативный буфер main, при `ask`
кладёт запрос в стор, при превышении предела показывает тост.

Источники текста:

| Протокол | Событие | `source` |
|---|---|---|
| SSH | `registerOscHandler(52, …)` + `parseOsc52` | `SSH · <вкладка>` |
| RDP | `remoteClipboardChangedCallback` | `RDP · <хост>` |
| VNC | событие `clipboard` noVNC | `VNC · <вкладка>` |

## §3 Общий диалог

`ClipboardAskDialog` (в `App` рядом с `DialogRoot`) показывает один запрос: откуда
текст, размер и обрезанный предпросмотр, кнопки «Скопировать / Не копировать».
Запрос в сторе один — новое событие заменяет предыдущее, потому что спрашивать про
устаревший текст бессмысленно.

## §4 Защита от эха

`createClipboardSync` разделён на две обязанности: `markRemote(text)` только
запоминает текст, пришедший с сервера (чтобы опрос не отправил его обратно), а
запись в локальный буфер делает политика. Раньше `applyRemote` копировал всегда —
именно это и обходило любую настройку.

## §5 Что не входит

- Политика на отдельный хост или протокол.
- Замена содержимого буфера на стороне сервера: VNC/RDP решают это сами.
- Отмена уже скопированного текста — буфер обмена Windows так не работает.
