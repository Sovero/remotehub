# Спецификация

## R01 — авто-показ после обновления

В `Settings` добавлено поле `lastSeenVersion: string | null` (в
`DEFAULT_SETTINGS` — `null`). В конце `init()` вызывается
`maybeShowWhatsNew()`:

- сохранённая версия отсутствует и онбординг не пройден → чистый первый
  запуск: версия запоминается, диалог не показывается (первый запуск
  обслуживает мастер-онбординг);
- сохранённая версия совпадает с текущей → «Что нового» для неё уже
  показывали, ничего не делаем;
- версии различаются → открывается диалог **«Что нового»** с changelog
  последнего релиза и кнопкой «Понятно».

## R02 — один раз на версию

`lastSeenVersion` обновляется на текущую версию в момент показа
(даже если диалог не открылся из-за другого открытого диалога/онбординга —
версия всё равно запоминается, чтобы не спрашивать на каждом старте).

## R03 — первый запуск

Условие «чистый первый запуск»: `lastSeenVersion === null && !onboardingDone`.
В этом случае версия запоминается без диалога — первое знакомство проводит
мастер-онбординг.

## Диалог «Что нового»

`WhatsNewDialog` (Modal, ширина 460): логотип, «Remote Hub обновлён»,
«Теперь у вас версия X.Y.Z», changelog последнего релиза (те же секции
и пункты, что в «О программе»), кнопка «Понятно». Тип `'whats-new'`
в `DialogState` и в `DialogRoot`.

## R04 — проверка

Смоук иконок дополнен (`whatsnew=1`): сценарий обновления — запоминаем
`lastSeenVersion: '0.0.1'`, вызываем `maybeShowWhatsNew()` → диалог
открывается с заголовком «Что нового», подзаголовком «обновлён» и пунктами
changelog; версия записана в настройках; после закрытия повторный вызов
ничего не открывает. Сценарий первого запуска: `lastSeenVersion: null` +
`onboardingDone: false` → диалог не открывается, версия запоминается.
Пройдено в dev и в собранном приложении.
