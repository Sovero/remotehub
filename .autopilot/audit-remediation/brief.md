# Изначальная задача

> Записано 2026-08-27. Этот файл не редактируется — он эталон, с которым
> сверяется готовый результат.

## Дословная команда пользователя

```
/autopilot full deep делай все что нужно
```

## Контекст, на который указывает команда

Команде предшествовал явный запрос пользователя провести аудит существующего
приложения Remote Hub (полное ТЗ приложено отдельным сообщением — SSH/Telnet/
RDP/VNC/SFTP менеджер на Electron) и отчёт о том, «что уже реализовано, что
сломано и что требуется исправить», без переписывания приложения с нуля.

По итогам аудита агент (в этой же сессии) провёл техническую проверку
(typecheck, тесты, сборку, историю CI-релизов) и представил пользователю
шесть находок с явной рекомендацией по порядку исправления. Пользователь в
ответ на прямой вопрос «Скажите, с какого пункта начать» ответил командой
`/autopilot full deep делай все что нужно` — то есть поручил агенту
самостоятельно определить и выполнить весь необходимый объём работы по
устранению найденного, без дальнейших уточняющих вопросов (`full`) и с
максимальной проработкой каждого пункта (`deep`).

Дословный текст находок аудита, зафиксированный как источник требований
(копия финального сообщения предыдущей фазы, без изменений):

1. «`src/main/index.ts` — 2125 строк, ~90% это встроенные smoke-тесты» —
   файл — точка входа Electron — содержит десятки веток
   `if (process.env.RH_SMOKE_*)`, каждая гоняет `executeJavaScript` с сотнями
   строк тестового JS прямо внутри продакшен-кода main-процесса. Прямое
   нарушение правила проекта «Keep files under 500 lines» и смешение
   ответственности.
2. «Мёртвый путь: COM-хост / MsRdpClient9 ActiveX всё ещё в проекте, но не
   вызывается из UI» — `RdpManager` встраивает `rdp-com-host.exe` (нативный
   C++, ActiveX `MsRdpClient9`) как дочерний HWND. `RdpEngine` в
   `shared/types.ts` — только `'iron' | 'rdpjs'`; `window.api.rdpLaunch`
   нигде не вызывается из renderer. Код остаётся в бандле, в
   `extraResources` (packaged в инсталлятор), покрыт тестами, но недостижим
   из интерфейса.
3. «SSH: нет проверки host key» — `config.ts` собирает `ConnectConfig` для
   `ssh2` без `hostVerifier`/`hostHash` — любой хост-ключ принимается молча.
   ТЗ явно требует «проверка host key». MITM не детектируется никак.
4. «Несогласованная (незакоммиченная) правка `electron.vite.config.ts`» —
   рабочая копия добавляет `output.intro` с
   `const __remoteHubNativeModules = ...`, но эта переменная нигде в проекте
   не используется — мёртвый код, который ничего не чинит.
5. «LogDialog не полностью покрывает ТЗ» — есть фильтр по уровню,
   копирование, очистка, live-update — но нет: фильтра по протоколу/
   источнику (`LogSource` уже хранит `rdp/iron/vnc/ssh/telnet/...`, но UI её
   не фильтрует), текстового поиска, экспорта в файл, отдельной кнопки
   «Скопировать диагностику». Рендер списка не виртуализирован.
6. «Незакоммиченные посторонние директории в корне» — `.agent-smith/`,
   `.autopilot/` (прежние прогоны), `.preview/`, `art/`, `diagrams/`,
   `docs/`, `landing/`, `scripts/gen-icon.cjs`, `scripts/render-excalidraw.cjs`,
   `tests/rdp-com-host.test.ts` — не входят в текущий коммит.

Рекомендованный агентом порядок (тоже дословно из отчёта): «(1) host key
verification в SSH — это реальная security-дыра; (2) решить судьбу
COM-хоста (оставить как явный fallback-engine или выпилить); (3) разгрузить
`main/index.ts`, вынеся smoke-тесты в `scripts/`; (4) доделать или откатить
незакоммиченную правку `electron.vite.config.ts`; (5) докрутить `LogDialog`
(поиск, фильтр по источнику, экспорт)».
