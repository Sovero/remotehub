# 01 — Проверка host key при SSH-подключении

**Требования:** R01, R01i.1, R01i.2, R01.1
**Blocked by:** нет
**Status:** ready

## Что должно заработать

Подключаясь по SSH к серверу первый раз, пользователь видит диалог с
отпечатком ключа сервера и подтверждает его перед тем, как сессия
откроется. Второй раз к тому же `host:port` диалог не показывается —
отпечаток уже известен и совпадает. Если отпечаток вдруг не совпал с
сохранённым (сервер переустановлен, подмена, MITM) — отдельный, заметно
более тревожный диалог со старым и новым отпечатком, без автоматического
принятия. Отказ от подтверждения — сессия не открывается, статус `error`
с понятным русским текстом, запись в журнале (`ssh`, warn).

## Из брифа, дословно

> «SSH: нет проверки host key... любой хост-ключ принимается молча. ТЗ явно
> требует «проверка host key». MITM не детектируется никак.»

## Как встроить (интеграционные точки, не переписывать заново)

- `ssh2` — хук `hostVerifier` в `ConnectConfig` (`src/main/sessions/config.ts`,
  `buildSshConfig`).
- Состояние сессии уже умеет `{ phase: 'auth-required', detail }` —
  `src/main/sessions/ssh-session.ts` уже показывает этот паттерн для
  keyboard-interactive (`client.on('keyboard-interactive', ...)`), новый код
  идёт по той же форме.
- IPC: `IPC.sessionAuth` (`shared/ipc-contract.ts`), обработчик в
  `src/main/ipc.ts` (`ipcMain.handle(IPC.sessionAuth, ...)`), preload-метод
  `sessionAuth` в `src/preload/index.ts` и его типы в `index.d.ts`.
- Renderer: `PasswordDialog.tsx` и `DialogRoot.tsx` — сегодня рендерят один
  и тот же диалог для любого `auth-required`; нужно различить обычный запрос
  пароля от host-key-запроса (по префиксу `detail`, см. Решения §1) и
  показать другой контент/кнопки для host-key случая (в т.ч. отдельный,
  более настойчивый вид для случая «ключ изменился»).
- Новый модуль `src/main/sessions/host-keys.ts` — персистентность в
  `userData/hostkeys.json`, паттерн внедряемой зависимости как у
  `src/main/store/index.ts` (путь к файлу и чтение/запись — через параметры
  конструктора, чтобы юнит-тест не трогал реальный диск).

## Критерии приёмки

- [ ] Первое подключение к новому `host:port` показывает диалог с
      алгоритмом и отпечатком, сессия ждёт ответа, не подключается молча
- [ ] Подтверждение отпечатка сохраняется и второе подключение к тому же
      `host:port` уже не спрашивает
- [ ] Изменившийся отпечаток даёт отдельное предупреждение (не тот же
      текст/вид, что у нового хоста), без кнопки «подключиться по
      умолчанию», старый и новый отпечаток видны в тексте
- [ ] Отказ от подтверждения переводит сессию в `error` с русским текстом
      и не оставляет открытого TCP-соединения; запись в журнале (`ssh`, warn)
- [ ] `tests/host-keys.test.ts`: put/get/isKnown/hasChanged на фейковом пути
      к файлу — без сети и без ssh2
- [ ] `npm run typecheck && npx vitest run` зелёные
