# 04 — Поиск, фильтр по источнику и экспорт в журнале событий

**Требования:** R05.1, R05.2, R05.3, R05.4, R05.5
**Blocked by:** нет
**Status:** ready

## Что должно заработать

В окне «Лог»: выпадающий список источников (SSH/RDP/IronRDP/VNC/…),
построенный из реально присутствующих в журнале значений; текстовый поиск
по подстроке сообщения; кнопка экспорта журнала в файл (системный диалог
сохранения); отдельная кнопка «Скопировать диагностику», которая берёт
версию приложения, нечувствительные настройки и последние 500 записей
независимо от текущего фильтра; список рендерит только последние 300
отфильтрованных записей с баннером «показаны последние N из M», если
записей больше.

## Из брифа, дословно

> «LogDialog... нет: фильтра по протоколу/источнику (`LogSource` уже
> хранит `rdp/iron/vnc/ssh/telnet/...`, но UI её не фильтрует), текстового
> поиска, экспорта в файл, отдельной кнопки «Скопировать диагностику».
> Рендер списка не виртуализирован.»

## Разделы спеки

Истории 8–12, Решения §5 (весь раздел, включая формат экспорта и лимит

## Как встроить (интеграционные точки)

- `src/renderer/src/components/dialogs/LogDialog.tsx` — уже есть
  `levelFilter`/`entries`/`copyAll`/`clearAll`; фильтр по источнику и поиск
  — тот же паттерн `useState` + `useMemo`.
- Список источников — `Array.from(new Set(entries.map(e => e.source)))`, не
  хардкод.
- Экспорт — новый IPC `logs:export` (main: `dialog.showSaveDialog` +
  `fs.writeFileSync`), т.к. `showSaveDialog` недоступен в renderer напрямую;
  канал добавляется в `shared/ipc-contract.ts` (`IPC` map), обработчик в
  `src/main/ipc.ts`, метод в `src/preload/index.ts`/`index.d.ts` — по
  образцу уже существующих `logsGet`/`logsClear`.
- «Скопировать диагностику» — целиком в renderer, без нового IPC: версия —
  через уже существующий `window.api.getAppInfo()`/`app:info`.
- Лимит рендера — `filtered.slice(-300)` для DOM; «Копировать»/«Экспорт»/
  «Диагностика» всегда берут полные (или намеренно расширенные для
  диагностики) данные, а не усечённый для рендера список.

## Критерии приёмки

- [ ] Список источников в фильтре строится из фактических `entries`, не
      захардкожен; выбор источника с 0 совпадений даёт отдельный empty state
- [ ] Поиск — регистронезависимый `includes()` по `message`, не `RegExp`
      (спецсимволы в тексте ошибки не ломают поиск); пустой запрос — 0
      совпадений даёт empty state со сбросом
- [ ] Экспорт сохраняет **отфильтрованный** (не усечённый рендером) список
      в выбранный пользователем файл; отмена диалога — без ошибки; сбой
      записи — toast с понятным текстом
- [ ] «Скопировать диагностику» — отдельная от «Копировать» кнопка,
      включает версию/Electron/arch и последние 500 записей независимо от
      текущего фильтра
- [ ] Список рендерит не более 300 отфильтрованных записей с баннером
      количества, если записей больше; операции экспорта/диагностики не
      подчиняются этому лимиту
- [ ] `tests/log.test.ts`: `logs:export` протестирован с моком
      `dialog.showSaveDialog`/`fs`, по образцу существующих моков `electron`
      в этом файле
- [ ] `npm run typecheck && npx vitest run` зелёные
