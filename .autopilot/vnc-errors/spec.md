# Спека: понятные сообщения об ошибках в VNC-вкладке

## Задача

VNC-вкладка при поломке подключения должна объяснять причину внятным текстом,
а не молчать. Бриф: «Добавить понятные сообщения об ошибках в VNC-вкладку для случаев,
когда сервер не отвечает на рукопожатие или требует не поддерживаемый тип шифрования».

## Диагностика (эмпирическая)

Проверен noVNC 1.7 (`node_modules/@novnc/novnc/core/rfb.js`): события `disconnect`
не несут reason, «Unsupported security types» уходит только в консоль (`Log.Error`).
Значит, внятного текста из noVNC не получить — причину может назвать только мост,
который видит сырые байты RFB-рукопожатия.

Заодно найден скрытый баг: `VncViewer` вызывал `rfb.connect()`, но в noVNC 1.7
публичного `connect()` у RFB нет — конструктор сам начинает подключение. Вызов падал
на **каждой** VNC-сессии, try/catch молча ронял вкладку в error с текстом
«rfb.connect is not a function», а happy-path смоук (проверка пикселей канваса)
этого не замечал: вьювер остаётся в DOM под оверлеем, кадр рисовался.

## Решение

1. **Мост следит за рукопожатием** (`src/main/vnc/bridge.ts`, класс `RfbHandshakeWatcher`):
   не вмешиваясь в пересылку байтов, разбирает фазы «версия → ответ клиента → security»
   и вызывает `onError` ровно один раз:
   - сервер молчит (10 с, по умолчанию) → «VNC-сервер не отвечает на рукопожатие.
     Проверьте адрес и порт (по умолчанию 5900)…»;
   - ответ не похож на RFB («RFB xxx.xxx\n») → «На этом порту работает не VNC-сервер…»;
   - в security нет ни одного поддерживаемого типа (None/VNC/TLS и др.) → сообщение
     с перечнем типов и советом включить авторизацию без TLS.
2. **Канал `vnc:error`**: мост → `VncManager` → IPC → preload → рендерер; сообщение
   ставит вкладке фазу `error` с текстом моста (детерминированно, мгновенно).
3. **Фолбэк-таймаут в `VncViewer`** (15 с): если фаза всё ещё `connecting` — ставит error
   с тем же внятным текстом. Не перезаписывает точное сообщение моста.
4. **Фикс скрытого бага**: вызов `rfb.connect()` удалён (конструктор noVNC 1.7 сам
   начинает подключение), `connect()` убран из `novnc.d.ts`.

## Решения по реализации

1. **Вотчер в мосте** — класс `RfbHandshakeWatcher` с фазами `version → client-version →
   security → done`; буферы фазы сбрасываются на переходах (иначе хвост баннера
   читался как счётчик security-типов — поймано тестом).
2. **Поддерживаемые типы** — `Set([1, 2, 6, 16, 19, 22, 30, 113])` по `_isSupportedSecurityType`
   в rfb.js noVNC 1.7.
3. **Сообщение ровно одно** — `reported`-флаг; соединение не рвём, закрытие вкладки уберёт мост.
4. **Смоук ошибки** — `.freebuff/silent-tcp.cjs` (принимает TCP и молчит) + ветка
   `RH_SMOKE_VNC_ERROR` в `src/main/index.ts` (ждёт оверлей до 20 с).

## Вне рамок

| Требование | Почему не сейчас |
|---|---|
| Перевод текстов ошибок | интерфейс приложения на русском; сообщения пишутся сразу по-русски |
| Подробная диагностика TLS-рукопожатия (X509) | мост ловит только факт «тип не поддерживается»; полный TLS-разбор — отдельная задача |
| Кнопка «Открыть в отдельном окне» при ошибке | не заказана; есть «Переподключить» |
