# Интерфейсы (что изменил полёт vnc-embed)

## Поведение

- **VNC-сессия открывается во вкладке**: noVNC рисует рабочий стол в канвасе `.vnc-canvas`.
  Раньше рукопожатие RFB зависало (мост терял баннер версии сервера) — канвас оставался чёрным.
- Отдельного внешнего окна для VNC в приложении нет ни в одном пути (проверено по коду и смоуком).

## Изменённые файлы

- `src/main/vnc/bridge.ts` — буфер `pending` для байтов TCP-сервера, пришедших до
  подключения WebSocket-клиента; flush в `wss.on('connection')`.
- `tests/vnc-bridge.test.ts` — новый тест гонки ранних байтов.
- `src/main/index.ts` — смоук `RH_SMOKE_VNC` теперь проверяет пиксели канваса
  («кадр отрисован»), а не только монтаж вьювера.

## Контракт для следующих тикетов

- `startBridge(host, port)` — сигнатура не менялась; семантика: байты от TCP-сервера
  буферизуются и доставляются WebSocket-клиенту при подключении.
- `RH_SMOKE_VNC=1` — смоук: двойной клик по хосту → `.vnc-wrap` → канвас с ненулевыми
  пикселями (до 8 с); вывод `[smoke] vnc flow OK — кадр отрисован (canvas=WxH:colored=N)`.
- Проба RFB-рукопожатия вне приложения: `.freebuff/fake-vnc-server.cjs` + `.freebuff/rfb-client-test.cjs`.
