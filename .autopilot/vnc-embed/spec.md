# Спека: VNC открывается внутри приложения

## Задача

Пользователь запускает VNC-профиль — и рабочий стол не оказывается внутри приложения.
Бриф: «VNC-протокол тоже открывается в отдельном окне — встрой его внутрь приложения
по аналогии с RDP».

## Диагностика (эмпирическая)

VNC-просмотрщик в приложении — noVNC (RFB в канвасе вкладки), отдельного внешнего окна
в коде нет ни для одного пути. Чтобы понять, что реально видит пользователь, смоук-прогон
был повторён против **реального RFB-сервера** (fake-сервер, протокол 3.8, без авторизации):

1. Вкладка открывалась, мост до VNC-сервера поднимался (TCP-connect успешен) — но канвас
   оставался чёрным, и сервер не получал ни одного байта рукопожатия.
2. Причина найдена: **мост терял ранний баннер RFB-сервера**. RFB-сервер отправляет
   «RFB 003.008\n» сразу после TCP-connect — раньше, чем noVNC (в рендерере) успевает
   открыть WebSocket до моста. Мост пересылал байты только уже подключённому
   WebSocket-клиенту (`wsClient`), а на момент баннера клиента ещё нет → байты дропались.
   noVNC ждёт версию сервера вечно → рукопожатие не происходит → чёрный канвас.

**Вывод**: VNC «не открывался внутри» из-за гонки в мосте, а не из-за отдельного окна.
Фикс — буферизовать байты от TCP-сервера до появления WebSocket-клиента и отдать их ему.

## Решение

`src/main/vnc/bridge.ts`: байты, пришедшие от TCP-соединения до подключения
WebSocket-клиента, складываются в буфер `pending`; при `connection` буфер сбрасывается
клиенту. После этого полное RFB-рукопожатие (версия → security → ServerInit → кадры)
проходит сквозь мост, и noVNC рисует рабочий стол во вкладке.

## Решения по реализации

1. **Буфер в мосте** (`src/main/vnc/bridge.ts`): `pending: Buffer[]`; в `tcp.on('data')`
   при отсутствии WebSocket-клиента — push; в `wss.on('connection')` — flush клиенту.
2. **Регрессионный тест** (`tests/vnc-bridge.test.ts`): TCP-сервер пишет баннер сразу при
   соединении, WebSocket-клиент подключается после и обязан получить баннер целиком.
3. **Смоук с пиксельной проверкой** (`src/main/index.ts`, ветка `RH_SMOKE_VNC`): теперь не
   просто «вьювер смонтирован», а «кадр отрисован» — выборка пикселей канваса через
   `getImageData`, ждём ненулевые до 8 с.

## Вне рамок

| Требование | Почему не сейчас |
|---|---|
| Собственный нативный VNC-клиент вместо noVNC (как IronVnc у RDM) | noVNC + мост уже даёт рабочий стол во вкладке; замена — отдельная крупная работа без пользовательской выгоды |
| Полный экран VNC внутри вкладки (вход в отдельный режим) | не заказано; есть кнопка «⛶ Полный экран» (Fullscreen API) |
