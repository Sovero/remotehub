# Спека: RDP внутри приложения

## Задача

Пользователь запускает RDP-профиль — и вместо того, чтобы рабочий стол открылся во вкладке
приложения, как SSH, VNC или SFTP, выскакивает отдельное системное окно Remote Desktop (mstsc).
Работа размазывается между приложением и посторонним окном: вкладка пустая, окно живёт своей
жизнью, закрытие приложения его не трогает, а переключение между серверами превращается в
жонглирование окнами. Бриф: «rdp-подключение открывается в отдельном окне, а должно открываться
внутри приложения — исправь».

## Решение

RDP-подключение в оконном режиме открывается прямо в рабочей области вкладки: как только сессия
стартует, окно Remote Desktop встраивается в панель вкладки и ведёт себя как часть приложения —
перемещается вместе с окном, масштабируется при изменении размера, прячется при переключении
вкладок и закрывается вместе с вкладкой или приложением. Исключение одно: профили с полным
экраном или мультимонитором физически не могут быть встроены (сам протокол RDP требует
полноэкранный режим) — они по-прежнему открываются отдельным окном, и приложение прямо об этом
говорит во вкладке.

## Решения по реализации

1. **Встраивание нативного окна mstsc как дочернего HWND окна Electron** (Win32 `SetParent`).
   Почему так: единственный способ сохранить полный нативный RDP-клиент (NLA, TLS, буфер обмена,
   смарт-карты) без внешних серверов. Chromium RDP не умеет, а библиотеки протокола RDP
   (rdpjs, node-freerdp) заброшены или требуют сборки C-библиотек. Доска-подложка в рендерере
   рисует статус, поверх неё ложится живое окно mstsc.
2. **Win32-вызовы через `koffi`** (N-API FFI). Почему: N-API не требует пересборки под Electron,
   koffi поставляет пребилт-бинари для win32-x64 и работает в packaged-сборке; в проекте сейчас
   нет ни одного механизма Win32 (DPAPI идёт через `safeStorage`). Вызовы ограничены user32:
   EnumWindows/GetWindowThreadProcessId (поиск окна по PID), SetParent, SetWindowLongPtrW,
   SetWindowPos, ShowWindow, PostMessage, IsWindow, SetForegroundWindow.
3. **Модуль встраивания отделён интерфейсом** (`RdpEmbedEngine`): юнит-тесты подменяют его фейком,
   реальный koffi загружается лениво и только на Windows. Тесты не зависят от GUI-сеанса.
4. **Геометрия**: рендерер измеряет панель вкладки (`getBoundingClientRect`, CSS-пиксели) и шлёт
   в main через IPC; main переводит в физические пиксели по `scaleFactor` дисплея
   (`screen.getDisplayMatching`) и вызывает `SetWindowPos`. Почему: координаты дочерних окон —
   физические пиксели клиентской области родителя; рендерер не знает scale factor.
5. **Жизненный цикл окна**: после запуска mstsc — найти его верхнеуровневое окно по PID процесса
   (опрос EnumWindows, до ~15 с), немедленно скрыть, `SetParent` в окно приложения, снять
   заголовок/рамку (WS_CAPTION, WS_THICKFRAME, WS_MINIMIZEBOX, WS_MAXIMIZEBOX, WS_SYSMENU),
   убрать кнопку из панели задач (снять WS_EX_APPWINDOW), позиционировать, показать. Сторож раз в
   ~2 с проверяет валидность HWND и перевстраивает, если mstsc пересоздал окно (переход
   «подключение → сессия»); периодический re-assert геометрии борется с собственным ресайзом
   mstsc под разрешение удалённого рабочего стола.
6. **Состояния вкладки** — без изменений контракта состояний: `connecting` (подложка «Запуск
   Remote Desktop…») → `connected` (встроенное окно) → `closed`/`error` (оверлей, как у SSH/VNC).
   Событие `rdp:exited` продолжает приходить из main.
7. **Режим фолбэка**: профили с `multiMonitor` или `screenMode: 'fullscreen'` не встраиваются —
   старый путь запуска отдельного окна; вкладка показывает честный статус «Режим полного экрана
   не встраивается — окно открыто отдельно».
8. **Режимы тестирования**: `RH_FAKE_RDP=1` (существующий) имитирует сессию без mstsc — смоук
   рендерера. Новый `RH_SMOKE_RDP_EMBED=1` запускает реальный mstsc против мёртвого порта и
   проверяет факт встраивания из main (найден HWND, установлен родитель), затем закрывает сессию.
9. **Упаковка**: `koffi` добавляется в `asarUnpack` (нативные .node-модули распаковываются из
   asar), иначе загрузка бинаря в packaged-сборке падает.

## Швы для тестов

- **`RdpEmbedEngine`** (интерфейс в `src/main/rdp/embed.ts`) — единственный шов для Win32.
  Юнит-тесты используют фейк: окно «появляется» после N опросов, все вызовы записываются и
  сверяются с ожидаемыми аргументами (SetParent с верным HWND, SetWindowPos с верным rect,
  ShowWindow SW_HIDE/SW_SHOW, PostMessage WM_CLOSE).
- **`RdpManager`** — выбор embed/fallback по настройкам профиля; поток launch → ready → exited;
  `stop` закрывает окно; сторож перевстраивает после «пересоздания» окна.
- Существующий `tests/rdp.test.ts` (генератор .rdp) — без изменений.
- Смоук-режимы рендерера `RH_SMOKE_RDP` (fake) и main `RH_SMOKE_RDP_EMBED` (реальный mstsc).
