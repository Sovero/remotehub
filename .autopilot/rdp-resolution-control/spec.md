# Спека: управление разрешением встроенной RDP-сессии

## Задача

Разрешение и режим (окно/полный экран) RDP-сессии задаются только в профиле. Пользователь
хочет менять их прямо из вкладки: выбрать разрешение и развернуть сессию на весь экран —
без редактирования профиля.

## Решение

Встроенная RDP-вкладка получает тулбар (строка над окном mstsc, его не перекрывает):

- **Разрешение** — выпадающий список (1024×768, 1280×800, 1366×768, 1600×900, 1920×1080,
  плюс текущее значение профиля, если его нет в пресетах). Выбор сохраняет новые
  `width`/`height` в профиль и переподключает сессию — mstsc стартует с новыми
  `desktopwidth`/`desktopheight` (.rdp-файл).
- **«⛶ Полный экран»** — сохраняет `screenMode: 'fullscreen'` и переподключает: mstsc
  открывается отдельным полноэкранным окном, вкладка показывает фолбэк «Remote Desktop
  открыт отдельным окном» с кнопкой **«Встроить во вкладку»** и тем же выбором разрешения.
- **«Встроить во вкладку»** (фолбэк) — сохраняет `screenMode: 'window'` и возвращает сессию
  во встроенный режим.

Переключение реализовано через `relaunchRdp(sessionId, patch)`: патч `RdpOptions` → сохранение
профиля в дерево → `reconnectTab` (закрытие текущей сессии + `rdp:launch` с новыми опциями).

Попутно исправлен латентный баг: фолбэк-режим (mode=window) не отслеживал процесс mstsc и не
закрывал его при stop() — полноэкранное окно оставалось жить после закрытия вкладки. Теперь
оба режима идут через единый путь (`spawnImpl` + `trackChild`), а `stop()` для window-режима
убивает процесс сразу (WM_CLOSE полноэкранному mstsc недоступен).

## Пользовательские истории

| # | Метка | История | Приёмка |
|---|-------|---------|---------|
| 1 | R01 | Как пользователь, я выбираю разрешение во вкладке — сессия переподключается с ним | смоук: после выбора 1024×768 вкладка снова embedded, select показывает 1024×768; профиль сохранён |
| 2 | R01.1 | …и разворачиваю сессию на весь экран / возвращаю во вкладку | смоук: «Полный экран» → фолбэк (mode=window), «Встроить во вкладку» → снова embedded |
| 3 | A01 | …и полноэкранное окно закрывается вместе с вкладкой | тест: stop() для mode=window убивает процесс; смоук-цикл не оставляет живых mstsc |

## Решения по реализации

1. `src/renderer/src/store.ts` — `relaunchRdp(sessionId, rdpPatch)`.
2. `src/renderer/src/App.tsx` — `RdpPane`: тулбар (разрешение + «Полный экран») над сценой
   (`rdp-stage` — новый целевой прямоугольник для встраивания); фолбэк получает «Встроить во
   вкладку» + выбор разрешения; для multiMonitor кнопка встраивания скрыта (режим невозможен).
3. `src/main/rdp/manager.ts` — единый путь запуска (`launchWindowed` через `spawnImpl`),
   `trackChild` для обоих режимов, `stop()` убивает window-режим сразу.
4. `tests/rdp-embed.test.ts` — фолбэк-тесты переведены на новый путь; новый тест «полноэкранный
   mstsc убивается при закрытии вкладки».
5. `src/main/index.ts` — смоук `RH_SMOKE_RDP_RESOLUTION`: окно → «Полный экран» → «Встроить во
   вкладку» → смена разрешения (реальный mstsc, живой порт).

## Вне рамок

| Требование | Почему не сейчас |
|---|---|
| Свободный ввод произвольного разрешения | пресетов достаточно для типичных сценариев; произвольное разрешение можно задать в профиле |
| Смена разрешения без переподключения (динамический ресайз сессии) | mstsc задаёт desktopwidth/height при подключении — менять их без переподключения нельзя |
