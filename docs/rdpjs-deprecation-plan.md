# План вывода из эксплуатации движка rdpjs (node-rdpjs-2)

**Дата:** 2026-09-04 · **Статус:** принят к исполнению · **Горизонт:** 3–4 релиза
**Связанные документы:** `docs/rdp-engine-risk-report.md` (риск R1, §4.1, §6.3),
`docs/swarm-patterns.md`

---

## 1. Резюме

Движок **Legacy canvas (rdpjs)** — единственный из трёх RDP-движков, где полный
протокольный стек исполняется в main-процессе Electron на неподдерживаемой
библиотеке node-rdpjs-2 ^0.3.5 (риск R1, высокий: история CVE в зависимостях —
CHANGELOG 0.1.28, привилегированный процесс, отсутствие таймаутов соединения).
План выводит его из эксплуатации за 3–4 релиза без потери пользовательских
сценариев, целевое состояние — **два движка: iron (основной) + legacy (COM-host,
запасной)**.

Поскольку единственная уникальная ниша rdpjs — «совместимость со старыми
сертификатами RDP-хостов», план содержит отдельный воркстрим по IronRDP (§3):
исследование показало, что наивная «релаксация проверки сертификата» технически
не закрывает проблему — вместо неё вводятся **детекция несовместимости + авто-фоллбэк
на legacy** (§3.3) и опциональный upstream/форк-трек (§3.4).

## 2. Целевая архитектура

```
renderer                         main
────────                         ────
IronRdpView (WASM-клиент)  ───►  RdpEngineHub ──► IronEngineAdapter   → iron-gateway (мост)
LegacyRdpView (HWND-панель)───►      │        ──► LegacyEngineAdapter → RdpManager (COM-host)
                                     └──────────► (rdpjs-адаптер — удаляется в фазе 6)
```

**Предусловие депрекации — единый хаб движков** (`src/main/rdp/engine-hub.ts`,
контракт `src/shared/rdp-engine.ts`): он делает удаление движка локальным
изменением (убрать адаптер из карты хаба) вместо правок в 10+ файлах.
Статус на 2026-09-04: контракт и хаб написаны и типобезопасны, но ещё **не
подключены** к `ipc.ts`/`index.ts` — подключение составляет фазу 1.

## 3. Воркстрим IronRDP: «последний сценарий» совместимости

### 3.1 Факты (проверено 2026-09-04 по WASM-бинарю 0.11.0 и апстриму)

1. **Валидация сертификата в WASM-клиенте уже ослаблена де-факто.** В бинаре
   присутствует CredSSP-перечисление ошибок `UntrustedRoot`,
   `CertificateUnknown`, `CertificateExpired` — при этом e2e-тесты проекта
   проходят против Windows-хостов с самоподписанными сертификатами. То есть
   классическая «галочка доверия» mstsc в IronRDP уже не блокирует.
2. **Настоящий блокер — не проверка, а согласование ключа.** Сертификаты части
   RDP-хостов несут `keyUsage` только с `keyEncipherment` (без
   `digitalSignature`) — в TLS 1.2 такой сервер способен предложить лишь
   статический RSA key exchange, который rustls принципиально не реализует
   (апстрим сознательно ограничивает транспортную безопасность —
   Devolutions/IronRDP#314). Рукопожатие умирает молча — именно этот кейс
   сейчас обслуживает rdpjs (и legacy).
3. **API релаксации в 0.11.0 отсутствует:** `SessionBuilder` не имеет
   сертификатных опций; есть открытый механизм `Extension` (апстрим добавляет
   протокольные расширения через него) и серверная часть моста уже отдаёт
   клиенту цепочку сертификатов (TLS-проба).

### 3.2 Следствие для плана

«Optional relaxed certificate check» возможен только в слое **валидации**
(и он уже включён de facto), но **не** в слое key exchange — rustls не даст.
Поэтому закрытие последнего сценария rdpjs строится на детекции + фоллбэке,
а не на ослаблении TLS.

### 3.3 Детекция несовместимости + авто-фоллбэк (фаза 3, реализуемо сейчас)

Мост уже обладает всеми данными: TLS-проба логирует протокол и шифр, а сторож
тишины (`tunnelSilenceTimeoutMs`) знает симптом «сервер молчит после CC».
Работы:

1. В `probeCertificates` классифицировать результат: если `certs.length > 0` и
   среди keyUsage сертификата нет `digitalSignature` (разбор X.509 через
   `node:crypto.X509Certificate`), добавить в состояние моста код
   `incompatible-server-cert`.
2. `IronRdpView`, получив ошибку с этим кодом, ставит вкладке состояние error
   с предложением: «Сертификат сервера несовместим с TLS-стеком IronRDP —
   подключиться через движок Legacy (COM-host)?» + кнопка переключения
   `rdpEngine: tab → 'legacy'` (механизм переподключения уже есть —
   `legacy-reconnect-${sessionId}`).
3. В `docs/` — короткий гайд администратору: перевыпуск сертификата RDP-хоста
   с `digitalSignature` (штатный self-signed Windows подходит — проблема
   только у кастомных сертификатов).

### 3.4 Опциональный upstream/форк-трек (фаза 7, только при необходимости)

Если после фоллбэка обнаружится класс пользователей, которым legacy недоступен
(кроссплатформенные сборки без Windows), — поднять апстрим-обсуждение
Devolutions/IronRDP: разрешить в `Extension` кастомный верификатор CredSSP и/
или альтернативный TLS-провайдер. Форк WASM-бинаря — аварийный вариант
(дорогое сопровождение: пересборка при каждом релизе апстрима). Вплоть до
этого момента rdpjs остаётся «бесплатным» запасом совместимости.

удаления на один релиз с переоценкой.

## 5. Чеклист удаления (фаза 6)

Код: `src/main/rdp/rdpjs-client.ts`, `src/renderer/src/components/RdpCanvas.tsx`,
`src/shared/node-rdpjs-2.d.ts`; rdpjs-адаптер и ввод в
`src/main/rdp/engine-hub.ts`; хендлеры `rdpjsLaunch/Close/Mouse/MouseMove/Wheel/
KeyUnicode/KeyScancode` в `src/main/ipc.ts`; broadcast `rdpjs:bitmap/state` в
`src/main/index.ts`; мост preload `rdpjs*` + `onRdpjsBitmap/onRdpjsState`;
`rdpjsLaunch/rdpjsClose` ветки в `src/renderer/src/store.ts` (openRdp/reconnect);
`RdpjsBitmapPayload/RdpjsStatePayload/Rdpjs*Event` и каналы в
`src/shared/ipc-contract.ts`; `'rdpjs'` в `RdpEngineId` (`src/shared/rdp-engine.ts`)
и в settings (`src/shared/types.ts`, `SettingsForm.tsx`, валидация patch в ipc.ts);
миграция сохранённых настроек и вкладок с `rdpEngine:'rdpjs'`.

Тесты: `tests/rdpjs-client.test.ts`, rdpjs-часть `tests/quick-fixes.test.ts` (R7
остаётся — перевести на чистые фикстуры), hub-тесты без rdpjs-адаптера.

Зависимости: `node-rdpjs-2` из `package.json` (+ транзитивные lodash и др. —
проверить `npm ls node-rdpjs-2`, `npm audit` после удаления).

Документы: правки в `docs/rdp-engine-risk-report.md` (R1 закрывается),
`docs/swarm-patterns.md` (упоминания движка), CHANGELOG 0.2.0.

**Откат:** вся фаза 6 — один набор правок в git; откат возвратом коммита и
восстановлением опции в settings (миграция `'rdpjs'` идемпотентна — старое
значение просто снова начинает валидироваться).

## 6. Риски плана

- **Скрытые пользователи rdpjs** (метрика фазы 2 локальна) — смягчение:
  вопрос в release notes + период фриза (фаза 5) перед удалением.
- **Фоллбэк-UX раздражает** — детекция должна срабатывать только на
  классифицированную несовместимость (§3.3.1), а не на любую ошибку моста.
- **Хаб-миграция затянется** — фазы 3–5 от неё не зависят (живут в текущей
  разводке), только фаза 6 опирается на фазу 1.
- **Апстрим-реабилитация IronRDP** (если RSA key exchange всё же появится в
  rustls/IronRDP) — план не меняется: rdpjs всё равно дублирует legacy.
